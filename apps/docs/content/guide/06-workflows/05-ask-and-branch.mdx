---
title: Let AI decide with Ask and Branch
description: Ask an AI model questions about each message, then send the message down a path for each answer.
---

An **If** step can only match text. When the rule is harder to write down, such as "is this a refund request?" or "which team should handle this?", use the two decision steps:

- **Ask** sends each message to an AI model with one or more questions.
- **Branch** reads the answer to one question and sends the message down the matching path, such as **Yes**, **No** or **Unsure**.

## Before you start

- **Your instance has to offer decision steps.** If **Ask** and **Branch** are not in the step palette under **AI**, your administrator has not turned them on.
- **AI has to be on for every mailbox that feeds the Ask step.** AI must be allowed in the workspace and turned on for each of those mailboxes. If it is not, the Ask step shows "Turn AI on for every mailbox that feeds this Ask step", and the workflow cannot be saved. See [Workspaces](/guide/workspaces) for the AI switches.
- **Decision steps cannot run before a message is sent.** You can use them after **When mail arrives**, **On a schedule** or **When run manually**, but not after **Before a message is sent**.

## Add an Ask step and its questions

<Steps>
  <Step title="Add the Ask step">
    Add **Ask** from the **AI** category of the step palette, or press **w** then **a** and search for it. Connect the output of a **Mailbox** step (or an **If** step) to the Ask step's input on the left.

    Click the Ask step. Its settings open in the Inspector on the right. You set everything below there.

  </Step>

  <Step title="Choose what the model sees">
    Under **Send to the model**, tick the parts of each message the model may read: **Sender**, **To**, **Cc**, **Subject**, **Snippet**, **Body**, **Has attachment** and **Date**. **Sender**, **Subject** and **Snippet** are ticked to start with. At least one has to stay ticked.

    Send only what the model needs. A long body is cut to its first 8,000 characters.

  </Step>

  <Step title="Add your questions">
    Under **Questions**, click one of the three buttons to add a question:

    | Button | Question type | The model answers with |
    | --- | --- | --- |
    | **+ Yes/No** | **Yes/No** | Yes or No |
    | **+ Pick one** | **Pick one** | One answer from a list you write |
    | **+ Rate** | **Rate** | One level from a scale you write |

    Type the question in its text box, for example "Is this email a request for a refund?". Questions can be up to 500 characters. You can change a question's type with the list next to its number, or remove it with **Remove question**.

    For **Pick one**, write at least two answers. Each answer has a name (up to 40 characters). Under it, an optional note (up to 200 characters) tells the model when to choose it. Click **+ Answer** to add another. An answer's **X** shows only when there are more than two. Leave **Offer “None of these fits”** on (it starts on) if a message might fit none of your answers.

    For **Rate**, write at least two levels under **Levels, lowest first**, for example Low, Medium and High. Each level has the same optional note. Click **+ Level** to add another.

    All the questions in one Ask step are asked together, in one go for each message. Each question gets its own output on the right of the Ask step: **Q1**, **Q2** and so on. The card lists the first two questions.

    <img src="/images/workflows/ask-step.png" alt="The Inspector for an Ask step with a Yes/No question, a Pick one question with three answers and a Rate question with three levels" class="dark:hidden" />
    <img src="/images/workflows/ask-step-dark.png" alt="The Inspector for an Ask step with a Yes/No question, a Pick one question with three answers and a Rate question with three levels" class="hidden dark:block" />

  </Step>

  <Step title="Write questions the model can answer well">
    The Inspector gives this advice under the questions: "Phrase each question positively, state the whole rule and its tie-breaks, and keep answers few and distinct." For example, ask "Does this email ask the reader to do something?" rather than "Is this email not just for information?".
  </Step>
</Steps>

If you remove a question or an answer that a connection still uses, the dialog **Remove connections?** asks you to confirm. Click **Remove** to remove the question and those connections, or **Cancel** to keep everything.

## Route mail with Branch steps

Each question needs its own **Branch** step to act on the answer. An Ask output can only connect to a Branch step, and a Branch step can only take its input from an Ask step.

<Steps>
  <Step title="Add and connect a Branch step">
    Add **Branch** from the **AI** category of the step palette. Drag from one of the Ask step's outputs, such as **Q1**, to the Branch step's input on the left. Until it is connected, the card says "Connect a question of an Ask step". Once connected, the card and the Inspector show the question, for example "Q1: Is this email a request for a refund?".
  </Step>

  <Step title="Set how sure the model has to be">
    The model gives each answer with a level of confidence. Click the Branch step. The sliders in the Inspector set how confident the model has to be:

    - For a **Yes/No** question: **Yes when at least** (80% to start with) and **No when at most** (20% to start with).
    - For **Pick one** and **Rate**: **Take the top answer at** (60% to start with).

    Anything that does not reach the line goes to **Unsure**. Higher values for **Yes when at least** and **Take the top answer at** send fewer messages down **Yes** or an answer path, and more to **Unsure**. For **No when at most**, a higher value sends more messages to **No**. Keep **No when at most** below **Yes when at least**. Otherwise the step shows "Set the No threshold below the Yes threshold", and the workflow cannot be saved.

    The card sums up the sliders, for example "Yes at 80% or more, No at 20% or less" or "Top answer at 60% or more".

    <img src="/images/workflows/branch-step.png" alt="The Inspector for a Branch step connected to a Pick one question, with its Take the top answer at 60% slider" class="dark:hidden" />
    <img src="/images/workflows/branch-step-dark.png" alt="The Inspector for a Branch step connected to a Pick one question, with its Take the top answer at 60% slider" class="hidden dark:block" />

  </Step>

  <Step title="Connect the paths you need">
    The Branch step has one output for each possible result:

    | Question type | Outputs |
    | --- | --- |
    | **Yes/No** | **Yes**, **No**, **Unsure** |
    | **Pick one** | One for each answer, then **Other** (when **Offer “None of these fits”** is on) and **Unsure** |
    | **Rate** | One for each level, then **Unsure** |

    Connect the outputs you want to act on, for example **Yes** to **Apply label**. You can leave the others unconnected. If the model declines to answer, the message goes to **Unsure**.

  </Step>
</Steps>

## Try your questions on recent mail

Before you save, you can see how the model answers your questions on real mail. Nothing in the mailbox changes.

1. Click the Ask step, then click **Try on recent mail** at the bottom of the Inspector. The button is greyed out until the step has a question.
2. A panel opens on the left, over the step palette. Pick a mailbox and click **Ask**. Only mailboxes with AI turned on are listed. If there are none, the panel says "No mailbox in this workspace has AI turned on."
3. The panel lists up to 10 of the newest messages in that mailbox's inbox. Under each subject and sender, it shows each question's answer and how sure the model was, for example "Q1: Yes 92%", and, for each connected Branch step, the path the message would take. "Refused" means the model declined to answer.
4. Click **Close** (the **X**) to close the panel.

## What happens when AI is not available

If AI is turned off for a mailbox, or decision steps are turned off on the instance, a run that reaches an Ask step does not fail. It is **blocked**, and the run details show the reason, for example "AI is turned off for this mailbox". Fix the cause, then retry the run. Questions that were already answered are not asked again. See [Cancel and retry runs](/guide/workflows/cancel-and-retry-runs).

In the run details, each message under a Branch step shows the path it took and how sure the model was, for example "Yes · 92%".
